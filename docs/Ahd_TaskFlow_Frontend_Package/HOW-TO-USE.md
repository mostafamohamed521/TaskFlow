# HOW TO USE — طريقة استخدام الحزمة

## قبل البدء

استلمي من مصطفى نسخة **كاملة** من مشروع `frontend/` الجاري تطويره، مش صفحة Dashboard منفصلة، ومعاها:

- أصل الشعار الرسمي وملفات الصور والخطوط المرخصة.
- تصميم App Sidebar/Topbar الرسمي، ومكتبة Forms/Modals/Toasts.
- بيانات Demo متفق عليها من أحمد (Projects/Workspaces/Members)، وآلاء (Tasks/Statuses/Assignees).
- مرجع بصري لكل شاشة عند إنشائها.

## الخطوة 1: توليد صور الـUI

افتحي أول ملف `01-UI-Design-Prompts/01-time-tracking-dashboard-UI-README.md`، وانسخي البرومبت كاملًا إلى أداة تصميم صور مع الشعار ومرجع الـDashboard الرسمي. اعتمدي التصميم. انتقلي للملف التالي وهكذا، مع الحفاظ على النظام البصري نفسه.

## الخطوة 2: تنفيذ الصورة في المشروع

افتحي ملف البرومبت المناظر تحت `02-Frontend-Implementation-Prompts/`، وأرفقي صورة التصميم المعتمدة ومجلد الـFrontend الحالي. أداة البرمجة يجب أن تُجري Audit للمشروع قبل تغيير الملفات، وتستخدم الصور للمطابقة البصرية، وتكتب أكواد منفصلة منظمة تحت المسارات المحددة.

## الخطوة 3: حافظي على وحدة البيانات

قبل أي تقرير، اتفقي على `projectId`, `taskId`, `memberId`, `workspaceId`. مصدر الوقت واحد. صفحة التقرير لا تخلق ساعات مختلفة عن صفحة Entries. Event Creation لا يخلق Task مكرر. Milestone للعميل لا يُنشر إلا بإذن واضح.

## الخطوة 4: ترتيب التنفيذ

- 01 → 02 → 03 → 04 → 05: Timer/Entries/Timesheets.
- 06 → 07: Calendar & events.
- 08 → 09 → 10: Gantt & Scheduling.
- 11 → 12 → 13 → 14 → 15: Reports.

## الخطوة 5: Integration & QA

- شغّلي المشروع على Live Server / HTTP محلي، مش `file://`.
- اختبري الروابط والاستيرادات، حالات Empty/Error/Loading، ومقاسات 1920،1440،1280،1024،768،430،390،360.
- اختبري بدء المؤقت من Task Details وظهوره في Time Tracking.
- اختبري تطابق أرقام التقارير مع سجلات الوقت والمهام.
- راجعي الفروقات بين Screenshot المرجع والصفحة الفعلية على نفس أبعاد الشاشة.
- اذكري الوظائف التي تحتاج backend بصراحة.

## تعليمات صارمة للأداة

- ممنوع إنشاء مشروع React أو Vite أو نسخة ثانية من `frontend`.
- ممنوع تعديل Public/Auth/Onboarding بدون سبب وتوثيق.
- ممنوع الضغط/تصغير ملفات HTML/CSS/JS في سطر واحد.
- ممنوع أرقام تحليلات وهمية لا تتطابق مع بيانات Demo.
- ممنوع مؤقت يشتغل تلقائيًا أو يراقب نشاط المستخدم في الخفاء.
- ممنوع افتراض وجود بيانات موظفين أو صلاحيات Backend حقيقية.
- ممنوع إضافة Emojis إلى واجهة TaskFlow.
