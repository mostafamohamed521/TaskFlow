# استخدام حزمة إيمان خطوة بخطوة

## قبل البداية

1. افتحي مشروع TaskFlow الحالي بالكامل، مش صفحة واحدة.
2. جهزي **اللوجو الأصلي**، Brand Board، صورة Shared App Shell المعتمدة، وأي UI منجز فعلاً في بقية الموديولات.
3. اقرئي `README.md` لتعرفي نطاق مسؤوليتك و`SHARED-DATA-CONTRACTS.md` لمفاتيح الربط والتسليم والمراجعات.
4. راجعي `FILE-STRUCTURE-AND-ROUTES.md` قبل تعديل الملفات أو نقل أي Component.

## لكل شاشة — نفس الخطوات

1. افتحي الملف المطابق من `01-UI-Design-Prompts/` وانسخي البرومبت كاملاً إلى أداة توليد الصور/التصميم **مع صور الهوية**. الصورة المطلوبة واحدة دقيقة عالية الجودة، وليست كود.
2. راجعي صحة العناصر والصلاحيات والأزرار وارتباط النسخ والطلبات. اعتمدي التصميم النهائي.
3. افتحي الملف المقابل من `02-Frontend-Implementation-Prompts/` وأرفقي **المشروع الحالي + صورة الشاشة المعتمدة + الشعار الأصلي** لأداة البرمجة.
4. الأداة تراجع المشروع أولاً، تحفظ الملفات الموجودة، تنفذ HTML/CSS/JS في المسارات المنطقية، وتختبر التفاعل والتجاوب.
5. احفظي نتيجة الشاشة واعرضيها على باقي الفريق. بعد مراجعة الـPR ابدئي الشاشة التالية.

## ملاحظات مهمة

- كل UI prompt يصف شاشة/واجهة وظيفية؛ ممكن تكون Modal أو Tab، ومش شرط تتحول إلى HTML مستقل منفصل عن الأب.
- لكل واجهة Path HTML مقترح لتسهيل الـDeep Link والاختبار، لكن لا تنفذي نسختين مختلفتين من نفس الفورم أو بياناته.
- لو المشروع الموجود بيستخدم naming convention سليمة مختلفة عن البرومبت، التزمي بالهيكل الحالي ووثقي المسار النهائي.
- اعملي روابط حقيقية فقط، وأي Action غير متوفر اشرحي إنه Demo/Unavailable بدل زر ميت.
- لا تستخدموا `file://` لاختبار ES Modules وfetch includes؛ شغلي Live Server أو local HTTP server.
- اطلبي Visual screenshot comparison من أداة البرمجة عند كل صفحة، ما تعتبرش الصورة مطابقة من غير مراجعة.

## ترتيب مراجعة الدمج

1. التنسيق مع مصطفى على Sidebar/Topbar/Forms/Toast/Modal.
2. التنسيق مع أحمد على Workspace/Project IDs.
3. التنسيق مع عهد على Milestone shared projection.
4. ربط Client Invitation creation مع مصطفى في شاشة القبول.
5. ربط Deliverables → Versions → Reviews → Change Requests → Public Activity بنفس Mock Data Source.

## Definition of Done

تعرض الشاشة بيانات صحيحة، تلتزم بحدود الخصوصية، تتجاوب، تدعم keyboard/focus، متصلة بالمشروع ولا تكسر شغل الغير، مع تقرير ملفات changed/created/issues.
